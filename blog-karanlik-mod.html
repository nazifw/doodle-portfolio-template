CSS değişkenleriyle karanlık mod: beyaz defter, siyah defter

Bu sitenin iki hali var: açık temada beyaz defter, siyah mürekkep; koyu temada siyah defter, beyaz mürekkep. Geçiş tek bir öznitelikle oluyor. Bu yazıda token yapısını, tercihi hatırlamayı, sayfa açılırken yanıp sönmeyi önlemeyi ve ay düğmesinden yayılan dairesel geçişi anlatıyorum.

Token'lar: renge değil, role isim ver

Karanlık modun sırrı, CSS'te renkleri hiçbir zaman doğrudan yazmamak. Her renk bir değişkenin (custom property) arkasında duruyor: --paper defterin zemini, --ink mürekkep, --pink ana vurgu. Bileşenler sadece bu isimleri kullanıyor. Koyu tema da bileşenlere dokunmuyor; aynı isimlere yeni değerler veriyor.

core.css 
:root {
  --paper: #fbfaf6;  /* defter zemini */
  --ink: #161714;    /* mürekkep */
  --pink: #c4501f;   /* adı pembe, kendisi pas: ana vurgu */
  --shadow-hard: 5px 6px 0 var(--ink);
  color-scheme: light;
}

[data-theme="dark"] {
  --paper: #121311;
  --ink: #f2f0ea;
  --pink: #e07a4a;
  /* siyah zeminde siyah gölge görünmez → kum tonlu gölge */
  --shadow-hard: 5px 6px 0 rgba(226, 194, 124, 0.28);
  color-scheme: dark;
}

body { background: var(--paper); color: var(--ink); }

Koddaki yoruma dikkat: --pink artık pembe değil. Sitenin ilk taslağında pastel bir palet vardı, sonra toprak tonlarına (haki, kum, pas) geçtim. Değişken adları aynı kaldı, sadece değerler değişti ve yüzlerce satır CSS'e dokunmadım. Yine de bugün baştan yazsam --accent gibi role göre isim verirdim; bu yüzden core.css'e --accent: var(--pink) gibi anlamlı takma adlar ekledim.

color-scheme satırını atlama. Bu özellik tarayıcıya kaydırma çubuklarını, form alanlarını ve otomatik doldurma renklerini de temaya uydurmasını söylüyor. Onu yazmazsan siyah defterin kenarında bembeyaz bir kaydırma çubuğu kalıyor.

Kağıt her temada kağıttır

Her şey değişkene bağlı olunca ters giden bir şey oldu: post-it'ler de koyu temada kararıyordu. Gerçek hayatta siyah bir defterin üstüne yapıştırdığın sarı not kağıdı sararmaya devam eder. Bu yüzden post-it ve polaroid gibi “fiziksel” nesneler iki temada da açık renk, üstlerindeki yazı her zaman koyu mürekkep. Kural basit: zemin ve mürekkep temaya uyar, üstüne yapıştırılan nesneler uymaz.

Tercihi hatırlamak

Kullanıcı ay düğmesine bastığında üç şey oluyor: <html> öğesine data-theme yazılıyor, seçim localStorage'a kaydediliyor ve diğer scriptler haberdar olsun diye bir olay yayınlanıyor. Düğmenin aria-pressed durumu da güncelleniyor; ekran okuyucu kullanıcısı düğmenin açık mı kapalı mı olduğunu duyabiliyor.

core.js 
btn.addEventListener("click", () => {
  const next = root.dataset.theme === "dark" ? "light" : "dark";
  root.setAttribute("data-theme", next);
  localStorage.setItem("theme", next);
  btn.setAttribute("aria-pressed", String(next === "dark"));
  document.dispatchEvent(new CustomEvent("doodle:theme", { detail: next }));
});

Kullanıcı hiç seçim yapmadıysa ne olacak? O zaman işletim sistemine soruyoruz: prefers-color-scheme: dark eşleşiyorsa siyah defterle açılıyoruz. Yani site, gece telefonunu karanlık modda kullanan birine ilk ziyarette bile göz kamaştırmıyor.

İlk boyamadaki beyaz flaşı önlemek

Tema kodunu sayfanın sonundaki JavaScript dosyasına koyarsan şu olur: tarayıcı önce HTML'i ve CSS'i okur, sayfayı varsayılan açık temayla boyar, ancak sonra script çalışıp koyu temaya geçer. Sonuç: koyu tema seçmiş kullanıcının gözüne her sayfa açılışında bir beyaz flaş. Çözüm, birkaç satırlık küçük bir betiği <head> içine, CSS'ten hemen sonra ve gövdeden önce koymak.

her-sayfa.html 
<head>
  <link rel="stylesheet" href="css/core.css">
  <script>
    (function () {
      var d = document.documentElement, t = null;
      try { t = localStorage.getItem("theme"); } catch (e) {}
      if (t === "dark" || (!t && matchMedia("(prefers-color-scheme: dark)").matches))
        d.setAttribute("data-theme", "dark");
    })();
  </script>
</head>

Bu betik senkron çalışır ve ilk boyamadan önce biter, bu yüzden sayfa doğrudan doğru temayla çizilir. try/catch gereksiz görünebilir ama bazı gizli pencerelerde localStorage'a erişmek hata fırlatır; hata olursa da sayfa sistem tercihine göre açılmaya devam eder. Sitenin dil tercihi (TR/EN) de aynı betikte aynı şekilde okunuyor.

Neden harici dosya değil?

Harici bir theme.js dosyası ağdan inene kadar sayfayı bekletir. Satır içi dört satır ise HTML ile birlikte gelir. Burada performans ile doğruluk aynı tarafta.

View Transitions ile dairesel geçiş

Tema anında değişebilir, ama defter temasında daha güzel bir şey mümkün: siyah mürekkep, ay düğmesinden başlayıp sayfaya bir daire gibi yayılıyor. Bunu View Transitions API ile yapıyorum. document.startViewTransition() tarayıcıdan eski ekranın bir fotoğrafını çekmesini, değişikliği uygulamasını ve yeni ekranın fotoğrafını çekmesini istiyor. Sonra yeni fotoğrafı bir clip-path dairesiyle açıyorum.

core.js 
const x = e.clientX, y = e.clientY;
// tıklanan noktadan en uzak köşeye mesafe = dairenin son yarıçapı
const r = Math.hypot(Math.max(x, innerWidth - x), Math.max(y, innerHeight - y));

if (document.startViewTransition && !reducedMotion) {
  const vt = document.startViewTransition(apply);
  vt.ready.then(() => {
    document.documentElement.animate(
      { clipPath: [`circle(0px at ${x}px ${y}px)`, `circle(${r}px at ${x}px ${y}px)`] },
      { duration: 700, easing: "cubic-bezier(.22,1,.36,1)",
        pseudoElement: "::view-transition-new(root)" }
    );
  });
} else {
  apply(); // desteklemeyen tarayıcı veya azaltılmış hareket: anında değiş
}

Ekran görüntüsünü alırken bir şey fark ettim: tarayıcı, eski ve yeni fotoğrafa varsayılan olarak bir de çapraz solma (crossfade) animasyonu uyguluyor. Dairenin dışında kalan eski görüntü yavaşça soluklaşıyor ve kısa bir an gri bir ara ton beliriyor. Dairenin tek başına çalışması için bu varsayılanı kapatmak gerekiyor:

tema.css 
/* varsayılan çapraz solmayı kapat: daire tek başına çalışsın */
::view-transition-old(root),
::view-transition-new(root) {
  animation: none;
  mix-blend-mode: normal;
}

View Transitions'ı desteklemeyen tarayıcılarda ve hareketi azaltmayı seçen kullanıcılarda tema yine değişiyor, sadece animasyonsuz. Efekt bir ödül; işlevin ön koşulu değil.

Kısaca

  • Renkleri hep değişkenle yaz; koyu tema yalnızca değerleri değiştirsin.
  • color-scheme ile kaydırma çubuğu ve form alanlarını da temaya uydur.
  • Fiziksel nesneler (post-it, polaroid) iki temada da kağıt rengi kalsın.
  • Tercihi localStorage'a yaz, yoksa prefers-color-scheme'a bak.
  • Temayı <head> içindeki satır içi betikle uygula: flaş yok.
  • View Transitions bir süs; desteklenmiyorsa anında geçiş yeter.
